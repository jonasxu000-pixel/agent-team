# 验证说明

## 可以确认的事实

0.3.2 开发阶段在独立的最小 Git 项目中完成了一次真实端到端工作流：Claude 读取包含随机标识的文件、原生 Edit 修改文件、原生 Write 创建文件，通过受控 MCP 测试接口触发原 runner 的真实隔离测试；协调器生成实际差异和提交，真实 Codex CLI 检查交付，独立集成工作区再次运行测试。

成功依据包括实际工具事件、文件内容、不可修改测试的哈希、Git diff/commit、模型回执及测试退出码，不是模型自述“完成”。这次验证属于受控小项目的工程验收。

## 公开仓库的证据边界

| 内容 | 范围 |
|---|---|
| 自动回归 | 模型及账单为 Mock/合成数据；Git、子进程与部分 Windows 边界实际运行 |
| Native Developer 真实验证 | 小型独立项目的 Read/Edit/Write、授权测试、交接、Codex 核验和集成回归 |
| 已知兼容限制 | 当前 Windows 完整链路、当前支持的 CLI 权限能力及 CaMeL 适配器 |
| 尚不代表 | 任意 shell、直接 Git Bash、所有项目框架、长时间多专家并行或复杂 UI 视觉质量 |

私有 Task ID、用户路径、认证、账单、金额、具体用量、机器信息和原始日志**不随源码发布**。公开仓库不提供这些私有材料的下载，也不把它们改写成可复用的价格保证。必要的财务测试数据已换成合成 fixture。

仓库中提供的手动验收程序是复现工具，不等于克隆仓库后已经完成真实验证。使用者需配置自己的安全 CLI 和已授权提供方，并明确批准费用。平台/CLI 版本变化后应重新检查能力，不通过无费用测试便声称所有真实工具可用。

## 运行公开测试

```powershell
python -m unittest discover -s tests -v
python scripts/check-publication.py
```

有本机 Codex sandbox 的 Windows 环境可执行额外 OS 边界测试；没有该依赖时相应测试明确跳过。自动测试不会主动调用付费模型。GitHub Actions 配置只运行这些无费用检查，不存模型凭据；在线 CI 状态以实际 Actions 结果为准。
